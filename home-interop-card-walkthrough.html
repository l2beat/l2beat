01 — the problem

It wasn't a responsiveness bug.
It was two different features.

The complaint was “the graph looks way different between xl and 2xl.” The actual cause: HomeInteropCard rendered two entirely different components for the selected-path details, switched by an xl:max-2xl class window.

A → B → A Different stat sets, different labels (“Per second” vs “Avg. value per second”), different net-flow formatting, CTA appears and disappears — depending on nothing but window width.

Worse, HomeInteropSelectedPath re-implemented the stat math that SingleChainStats / MultipleChainsStats already own on the summary page — a guaranteed drift trap where the two copies diverge a little more with every edit.

The diagnosis that shaped everything

The divergence has two independent axes. Placement (beside the graph vs. below it) may legitimately change with available width — that's responsive design. Content (which stats, which labels, which actions) must never change — that's just two features wearing the same name. Fix: pin the content, free the placement.

02 — decisions

Five decisions, each with the road not taken

Decision 01

The compact panel survives; the summary panel leaves the card

HomeInteropSelectedPath is the single selected-path component at every width. It fits all placements — including the height-constrained third column of the 3-column home grid, and mobile. The home card is a teaser; depth lives one click away.

REJECTED — using FlowsSelectedPathPanel everywhere. Its full stack (stats + 3 routes + token list + bridge list + button) doesn't fit below the graph in the narrow 2xl column without scrolling, and adding a “compact mode” prop would reintroduce the exact per-breakpoint divergence being removed.
Decision 02

Stats come from the summary page's own helpers

The rewritten panel derives every number from getChainFlowStatItems and getPairFlowStats — the same functions SingleChainStats / MultipleChainsStats use. Labels and values are now byte-identical with /interop/summary, and the duplicated math in the home component is deleted. Drift is structurally impossible.

Side effect: the home card gained rows it never had — Avg. transfer time, Unique tokens, Transfers in/out. Single chain now shows the summary's exact 12 rows; a pair shows its exact 6.

REJECTED — keeping the hand-rolled 8-stat set and only fixing labels. Cheaper diff, but the two stat pipelines would remain and re-diverge.
Decision 03

Container queries replace viewport breakpoints

“Is this card wide enough for a side panel?” is a question about the card, not the window. And card width is not monotonic in viewport width: the card is full-page-width below 2xl, then shrinks to a ~500–700px column above it. That's precisely why the old code needed the weird xl:max-2xl window. @container on the card + @min-[900px]: on the layout makes the decision track actual card width.

Why 900? The graph wants ≥ ~600px to breathe, plus the 280px panel, plus the gap. Bonus fixes for free: ultrawide screens (where the third column grows past 900px again) get the side panel back, and awkward in-between lg widths resolve correctly with no extra cases. @min-[…px] arbitrary values follow the existing repo convention (see TopRoutesWidget, ProtocolsPieChart).

REJECTED — patching with more viewport windows (lg:max-2xl, min-[2200px]:…). Each new page-grid change would break the mapping again.
Decision 04

The panel measures itself too

The panel is its own @container. Its stat grid is 1 column under 300px of panel width, 2 columns above. So in the 280px side column it stacks; below the graph it spreads — without the panel ever knowing why it has the width it has. Nesting works because a container variant resolves against the nearest ancestor container: the panel root's classes answer to the card, its children answer to the panel.

REJECTED — a placement prop passed down from the card. Works, but it's exactly the coupling container queries exist to delete.
Decision 05

One hint position, one CTA, everywhere

The “select a chain” hint used to live above the graph in side-panel mode and inside a placeholder box below it otherwise. Now it's always above the graph; the placeholder box and its min-h-[180px] reservation are gone. The summary panel's CTA was grafted onto the compact panel: a pair deep-links to /interop/summary?from=…&to=… via buildInteropUrl, a single chain links to {chain.href}#interop-flows (absent when the chain has no project page — same rule as the summary). mt-auto pins it to the bottom when the side column stretches the panel.

Small things worth knowing

  • tailwind-merge is safe here — mt-4 and @min-[900px]:mt-0 are distinct groups, so the per-breakpoint override rule that bites with md: padding doesn't apply.
  • FlowsGraphPanel needed nothing — it already sizes via ResizeObserver, i.e. it was container-driven before the rest of the card caught up.
  • The 280px header wrap — “Selected path” broke mid-word in the side column; fixed with flex-wrap + shrink-0 on the title so the subtitle wraps as a unit instead.
  • React Query dedupes — the panel receives data from the card rather than re-querying, so unifying components didn't add a request.
