02 / OBSERVATIONS FROM THE COMPILER
Syntax becomes facts

          
The compiler supplies the AST and storage layout. A small adapter copies observations from the AST. It does not decide what can execute.

          
Readable labels, same IDs. For example, 12_use_score means “the use of score at AST node 12”; 3_state_score means “the state declaration at node 3”. A reference connects the use to its declaration. The number identifies the node; the suffix is a display label, not Soufflé syntax. Compiler JSON and downloaded facts retain the original numeric IDs.
            

          

            
The AST, as a tree

            
Each branch is a child(parent, node) fact. Expand a node to see its direct children. These are syntax relationships, not execution order.

            
Try expanding ContractDefinition → setScore → Block → ExpressionStatement → Assignment. The assignment contains the identifiers for score and next.

03 / DERIVATION
Direct assignments
3 clauses

            
withinFunction walks AST children. directWrite joins an assignment with the state declaration its left side refers to.

            
A comma means and. :- means if. Repeated variables connect the tuples. _ means “any value”.
