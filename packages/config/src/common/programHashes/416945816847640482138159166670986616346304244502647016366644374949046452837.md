These steps reproduce the 1,182-felt SHARP outer bootloader on Linux with Docker and Foundry `cast`.

1. Download the exact public source revision (Cairo v0.14.4a0):

```bash
mkdir cairo-lang && curl -sL https://codeload.github.com/starkware-libs/cairo-lang/tar.gz/d435ed7003919b3842a48fc07bbb06a08ed9bbad \
  | tar -xz -C cairo-lang --strip-components=1
```

The entrypoint is `src/starkware/cairo/bootloaders/bootloader/bootloader.cairo`. Its Bazel target uses `--proof_mode --debug_info_with_source`. Debug info is not part of the program hash.

2. Compile it in proof mode with the compiler of the same revision, and print its Pedersen program hash. The released `cairo-lang` package is only installed for its Python dependencies:

```bash
mkdir out && docker run --rm -v "$PWD/cairo-lang/src:/src:ro" -v "$PWD/out:/out" python:3.9-bookworm sh -c '
  apt-get update -qq && apt-get install -y -qq libgmp3-dev
  pip install -q cairo-lang==0.14.0.1 && pip uninstall -q -y cairo-lang
  export PYTHONPATH=/src
  python -m starkware.cairo.lang.compiler.cairo_compile \
    /src/starkware/cairo/bootloaders/bootloader/bootloader.cairo \
    --cairo_path /src --proof_mode --output /out/bootloader_compiled.json
  python -m starkware.cairo.bootloaders.hash_program \
    --program /out/bootloader_compiled.json --program-hash-function pedersen'
```

The printed hash, converted to decimal, should be the program hash. The instruction array is in the `"data"` field of `out/bootloader_compiled.json`.

3. Check that the compiled instruction array is identical to the one pinned by the immutable Ethereum contract at `0x8ad2429Dbd77ECe844ED28222b26798A9449C2F3`:

```bash
cast call 0x8ad2429Dbd77ECe844ED28222b26798A9449C2F3 \
  'getCompiledProgram()(uint256[1182])' \
  --rpc-url "$ETHEREUM_RPC_URL" \
  --json > sharp_outer_bootloader_onchain.json
```

All 1,182 felts should be equal.
