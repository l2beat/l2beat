This value is not a hash of a single program. It is a Pedersen hash chain over four commitments, listed in [bootloader_config_hash.json](https://github.com/starkware-libs/cairo-lang/blob/d435ed7003919b3842a48fc07bbb06a08ed9bbad/src/starkware/cairo/bootloaders/bootloader/bootloader_config_hash.json) at cairo-lang `d435ed7003919b3842a48fc07bbb06a08ed9bbad` (v0.14.4a0). The steps below reproduce every commitment from public source on Linux with Docker. Step 4 needs about 70 GB of memory (RAM plus swap).

1. In an empty working directory, download cairo-lang and start a Python 3.9 container with the compiler of the same revision. The released `cairo-lang` package is only installed for its Python dependencies. The working directory is mounted at `/host`, so keep the proving checkout of step 2 and the two helper scripts in it:

```bash
mkdir cairo-lang out && curl -sL https://codeload.github.com/starkware-libs/cairo-lang/tar.gz/d435ed7003919b3842a48fc07bbb06a08ed9bbad \
  | tar -xz -C cairo-lang --strip-components=1
docker run --rm -it -v "$PWD/cairo-lang/src:/src:ro" -v "$PWD/out:/out" -v "$PWD:/host:ro" \
  python:3.9-bookworm bash
apt-get update -qq && apt-get install -y -qq libgmp3-dev
pip install -q cairo-lang==0.14.0.1 && pip uninstall -q -y cairo-lang
export PYTHONPATH=/src
```

Inside it, compile the two simple bootloaders and the circuit applicative bootloader in proof mode:

```bash
B=/src/starkware/cairo/bootloaders
for P in simple_bootloader/simple_bootloader \
    simple_bootloader/no_builtin_simulation_simple_bootloader \
    circuit_applicative_bootloader/circuit_applicative_bootloader; do
  python -m starkware.cairo.lang.compiler.cairo_compile $B/$P.cairo \
    --cairo_path /src --proof_mode --output /out/$(basename $P)_compiled.json
done
```

2. Reproduce the circuit verifier program hash in `circuit_applicative_bootloader/circuit_verifier_program_hash.json`. Install [scarb](https://docs.swmansion.com/scarb/) 2.18.0 and build the verifier from the [proving](https://github.com/starkware-libs/proving) repository at `e0035ffc8e08da270b8cb4a71f3708af70c2c775`:

```bash
git clone https://github.com/starkware-libs/proving.git && cd proving
git checkout e0035ffc8e08da270b8cb4a71f3708af70c2c775
SCARB_TARGET_DIR=$PWD/target_circuit scarb \
  --manifest-path stwo_cairo_verifier/Scarb.toml --profile proving \
  build --package stwo_circuit_verifier --features qm31_opcode
```

Hash `/host/proving/target_circuit/proving/stwo_circuit_verifier.executable.json` in the container of step 1 with [hash_stwo_verifiers.py](/files/starkware_proghash_artifacts/cf9bf972bede402a125e8638bb258e77563ae933/hash_stwo_verifiers.py). Its blake hash should be the committed value.

3. Reproduce `circuit_applicative_bootloader/production_circuit_registry.json`, which holds the five leaf verifier circuit hashes and the multiverifier circuit hash. In the same proving checkout, with the Rust toolchain from `rust-toolchain.toml`:

```bash
cargo build --release -p circuit-params
target/release/circuit-params --registry \
  --definition circuit_registry_definitions/production/definition.json \
  --output-path production.json
```

The JSON content of `production.json` should equal the committed registry. The registry is generated for `leaf_simple_bootloader_compiled.json` in the proving repository. Its instruction array equals the one of `simple_bootloader/leaf_simple_bootloader.cairo` compiled from cairo-lang as in step 1.

4. Reproduce the 30 entries of `supported_cairo_verifier_program_hashes` in `bootloader/supported_program_hashes.json`:

- Entries 1-7, 11-17 and 21-27 are the 21 Stone Cairo verifier hashes. They are the same as in v0.14.3, reproduce them following [these steps](/files/starkware_proghash_artifacts/cf9bf972bede402a125e8638bb258e77563ae933/stone_verifier_steps.md).
- Entries 8-10, 18-20 and 28-30 are the pedersen, poseidon and blake hashes of three Stwo Cairo verifier builds. StarkWare builds them from a `cairo-verifier-frozen` branch of the proving repository that is not public. The same programs build from `e580a502ca2a9a795ac6e971009ed899621df54a`, the last public commit that contains the verifier. Run this in the proving checkout of step 2:

```bash
git checkout e580a502ca2a9a795ac6e971009ed899621df54a
for FEATURES in poseidon252_verifier,poseidon_outputs_packing \
    qm31_opcode,poseidon_outputs_packing qm31_opcode,blake_outputs_packing; do
  SCARB_TARGET_DIR=$PWD/target_$FEATURES scarb \
    --manifest-path stwo_cairo_verifier/Scarb.toml --profile proving \
    build --package stwo_cairo_verifier --features $FEATURES
done
```

Hash each `/host/proving/target_<features>/proving/stwo_cairo_verifier.executable.json` with `hash_stwo_verifiers.py` and compare with the entries above, in this build order within each group. The pedersen hashes take several minutes each.

5. In the container of step 1, recompute the four commitments and the config hash with [hash_bootloader_config.py](/files/starkware_proghash_artifacts/d435ed7003919b3842a48fc07bbb06a08ed9bbad/hash_bootloader_config.py):

```bash
python /host/hash_bootloader_config.py /src /out
```

Every line should end with `MATCH`. The last line prints the program hash.
