Since 2026-09-07 (block 25924899, tx `0x7f1b7013…cded482`) the respected game type is the PermissionedDisputeGame (type 1): the RoninConduitOwner Safe, acting as Guardian, called `setRespectedGameType(1)` on the AnchorStateRegistry, moving withdrawals off the Kailua ZK game (type 1337) that had been respected since 2026-07-01. The Kailua contracts (KailuaGame implementation, KailuaTreasury, KailuaVerifier and the RISC Zero verifier set) remain deployed and `game1337` is still registered in the DisputeGameFactory, but Kailua proposals stopped on 2026-09-07 and Kailua games created after the change are not respected for withdrawals; Kailua games created before it remain valid once resolved.

The permissioned games commit to the op-program v1.3.1 absolute prestate (`0x038512e0…6764d54c`, reproduced from the op-program/v1.3.1 release). That binary embeds the superchain-registry snapshot at commit 42bd03ba8313 (2024-08-21), which lists 17 chain IDs and does not include Ronin (chain ID 2020), and predates Ronin's custom gas token and EigenDA derivation. When the program boots for chain ID 2020 it fails to load a rollup config and panics, so a dispute stepped through to the VM cannot produce a correct result and any claim, honest or fraudulent, can be countered against the panic. Only the permissioned proposer can create state proposals and only the proposer and challenger can move or step, so the proof system reduces to an operator-attested delay timer rather than an adversarial fraud proof. Fixing this requires redeploying the games with a chain-specific prestate, or returning the respected game type to Kailua.
