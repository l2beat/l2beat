The vault's verifier, signing keys, note lifetime, expiry bucket and escape delay are fixed by its code and constructor. The linked Poseidon library is also fixed. The request and withdrawal verification keys cannot be replaced within this deployment.

The discovered vault owner can change the treasury, pause and unpause deposits and user-initiated withdrawal routes, transfer ownership or renounce it. Ownership changes are resolved through discovery. There is no enforced notice period before a pause. Already pending escapes, challenges and expired-note sweeps continue during a pause. Keeping the vault paused until an active note expires allows its full balance to be swept to the treasury, which the owner can redirect. [Verified vault source](https://etherscan.io/address/0x4386FDbdA35D995beB3BF8625118Ec5982ec81fe#code).

The operator holds the offchain state and clearance signing keys pinned in the vault. It controls API lease issuance, settlement signatures and immediate withdrawal clearance. State signatures bind commitments and deployment context. They do not give the key holder an ordinary onchain call permission or reveal note secrets. There is no public onchain evidence mapping these Baby-JubJub keys to an Ethereum account, so the discovered owner is not assumed to hold them.

The service operator, credential issuer, key verifier and inference provider control availability beyond Ethereum. The operator needs retained request proofs and a functioning challenger to reject stale-state escapes before their deadlines. API cost and service delivery are offchain trust assumptions. A lost signing key or missing settlement transcript cannot be remedied by rotating keys in this vault.

Open Anonymity controls the hosted application and its packaged endpoint, deployment and artifact pins. A browser update can change future instructions and access locally stored note state. An inspected local build preserves reviewed pins, but still needs compatible operator signatures, credential issuance and inference services. The mainnet profile in the public SDK currently pins a different verifier endpoint from the hosted mainnet app. Review the production profile before using that SDK build. [Public profile](https://github.com/ethereum/zkapi/blob/045b444ea1b52538d1b40273c7cb6ed09468a052/sdk/assets/config/mainnet.json), [hosted profile](https://chat.openanonymity.ai/zkapi/browser-config.json).
