The verification steps are based on [this guide](https://github.com/scroll-tech/scroll-sc-tools/pull/11), with two
adjustments to make the regeneration reproducible:
- Formatting. The verifier generated by the guide's `--recompute` mode has the same executable code as the deployed one but a different codehash because of different formatting.
- Setup params. Degrees 22 and 23 are required, not the 22 and 24 in the script.

Memory usage peaks around 30 GiB on an Ubuntu machine.

1. Install dependency packages: `sudo apt-get update && sudo apt-get install build-essential pkg-config libssl-dev`.
2. Install the required Rust toolchains, Solidity compiler and Foundry:
```
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
. .cargo/env
rustup toolchain install nightly-2025-11-20   # used by scroll-sc-tools; OpenVM's generator uses stable

cargo install svm-rs
svm install 0.8.19
solc --version  # should be 0.8.19

curl -L https://foundry.paradigm.xyz | bash
source ~/.bashrc    # or similar depending on your shell
foundryup
```

3. Clone the [scroll-sc-tools](https://github.com/scroll-tech/scroll-sc-tools) repo and check out the PR #11 commit:
`git checkout f105d1dcdf0d945f2a3028a4f557ab9369486c1a`.
4. Modify the script to download all required trusted setup params: line 8 of `scripts/download-params.sh` should be changed to `degrees=("22" "23" "24")`.
5. Download trusted setup params (around 4 GiB): `bash scripts/download-params.sh`.
6. Clone the [openvm-solidity-sdk](https://github.com/openvm-org/openvm-solidity-sdk) repo at tag v2.0 and build OpenVM's verifier generator:
```
git clone https://github.com/openvm-org/openvm-solidity-sdk.git 
cd openvm-solidity-sdk
git checkout 7dc4d9936834e75d3e08186f0c757418858715df   # tag v2.0
cargo build --release --locked --manifest-path tools/generate-verifier/Cargo.toml --bin generate-verifier
```
7. Regenerate the verifier (Scroll uses the deferral variant): `tools/generate-verifier/target/release/generate-verifier --variant deferral --output-dir generated`.
8. Format the generated sources with the repo's forge fmt config and check they are byte-identical to the published
sources. The diff should print nothing:
```
cp foundry.toml generated/
forge fmt --root generated
diff -r -x '*.json' generated/src/v2.0-deferral src/v2.0-deferral
```
9. Compile the published sources (now shown identical to the regenerated ones) with the exact settings of the deployment,
and print the codehash. It should be `0x00dfb6855747412fa70b8a75aaa4950f1deafaace9d2a4e9923ad2e1a3589928`:
```
cd scroll-sc-tools
cargo run --release -- generate-verifier
```
10. Verify that the deployed verifier smart contract has the same codehash: `cast keccak $(cast code 0x0d2A59fd7060460F07c30C2817b4E79576da01C6 --rpc-url <YOUR_ETHEREUM_RPC_URL>)`.
